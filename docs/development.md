# Development and verification

Follow [repository instructions](../AGENTS.md) and the [current specification](specification.md). Behavior changes use failing domain tests followed by implementation and green checks. This covers hierarchical views, root/author weighting, grouped calibration, contrast-bank exclusions, training-only hard-negative discovery, guarded development ablations, eligible negative inputs, blind synthetic prompts/retries, required manual source-fit evidence before signal approval, explicit non-human source validation, tracked/untracked transitive provenance, copying gates, required manual labels, generator rotation, lineage caps, synthetic diagnostics, checksummed public email acquisition with exact message selectors, ignored local training bodies, frozen production choices and stale-artifact invalidation. Unexpectedly passing tests are inspected before adding implementation. Generated verification output stays in ignored artifacts.

The default suite replaces only the external encoder boundary. Performance behaviors cover runtime device resolution, explicit failure, dtype-sensitive cache identity, FAST/deep score equivalence and bounded deletion work, batch ordering/OOM retry, inference mode and the deterministic precision gate. A separately marked real MPS test verifies warm-up and finite 512-dimensional embeddings. Warm hardware measurements and precision acceptance remain local benchmark evidence rather than CI timing assertions. It covers median scoring, fold/reference/calibration exclusions, email cleanup throughout feature measurement and scoring, unknown-author fallback, duplicate-root diagnostic inventories, persistence, CLI behavior, local self-editor API validation/readiness/model reuse, exact plain-text offsets across Unicode/CRLF/repeated sentences, safe errors, candidate-cache cleanup and private-input nonpersistence, simplified collapsed reports with explicit negative-source split attribution and historical holdout count reconciliation, fold-local nested threshold decisions, combined-score ranking metrics, production-threshold separation, persisted outer predictions and technical threshold stability diagnostics, final weighted character materiality boundaries and frozen feature persistence, privacy and documentation policy. The separately marked real-checkpoint smoke test remains available; real-corpus reevaluation and production refitting verify the pinned encoder without using historical results for selection. CPU inference uses one worker thread on macOS to avoid native OpenMP conflicts.

The documentation checker validates the maintained inventory and local links, including entry points for the reusable synthetic-generation procedure. Git-included files and prospective source/test files are scanned against private prose windows; literal scans cannot certify every short phrase or paraphrase. Private positive inputs, other-author email inputs, generated artifacts, caches and prototype remain ignored. Production code never imports prototype. Public attribution, pinned provenance and license terms remain preserved, including clearly separated attribution for removed historical sources. See [evaluation](evaluation.md) for uncertainty and report interpretation.

Self-editor rendering helpers are tested with the dependency-free `tests/web_helpers.cjs` script using a standard JavaScript runtime. It verifies escaping, Unicode offsets, range ordering/overlap safety, exact rendered source and score comparison. Run the default pytest suite and documentation checker before live testing. Browser verification then exercises the real production backend, editing/reanalysis, highlight explanations, stale/error/loading states and responsive appearance; use invented candidate text and keep any generated evidence under ignored artifacts.
