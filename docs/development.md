# Development and verification

Follow [repository instructions](../AGENTS.md) and the [current specification](specification.md). Behavior changes use failing domain tests followed by implementation and green checks. This covers hierarchical views, root/author weighting, grouped calibration, contrast-bank exclusions, training-only hard-negative discovery, guarded development ablations, eligible negative inputs, checksummed public email acquisition with exact message selectors, ignored local training bodies, frozen production choices and stale-artifact invalidation. Unexpectedly passing tests are inspected before adding implementation. Generated verification output stays in ignored artifacts.

The default suite replaces only the external encoder boundary. It covers median scoring, fold/reference/calibration exclusions, email cleanup throughout feature measurement and scoring, unknown-author fallback, duplicate-root diagnostic inventories, persistence, CLI behavior, simplified collapsed reports with nested selection summary metrics, final weighted character materiality boundaries and frozen feature persistence, privacy and documentation policy. The separately marked real-checkpoint smoke test remains available; real-corpus reevaluation and production refitting verify the pinned encoder without using historical results for selection. CPU inference uses one worker thread on macOS to avoid native OpenMP conflicts.

The documentation checker validates the maintained inventory and local links. Git-included files and prospective source/test files are scanned against private prose windows; literal scans cannot certify every short phrase or paraphrase. Private positive inputs, other-author email inputs, generated artifacts, caches and prototype remain ignored. Production code never imports prototype. Public attribution, pinned provenance and license terms remain preserved, including clearly separated attribution for removed historical sources. See [evaluation](evaluation.md) for uncertainty and report interpretation.
